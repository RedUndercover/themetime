# Packaging and releases

This is the maintainer runbook for validating and publishing ThemeTime
releases. User installation and removal instructions are in
[Getting started](getting-started.md).

ThemeTime uses GoReleaser v2 to publish Linux x86-64 artifacts:

| Artifact | Purpose |
| --- | --- |
| `themetime_VERSION_linux_amd64.pkg.tar.zst` | Native Arch Linux package |
| `themetime-VERSION-linux-x86_64.tar.gz` | Portable archive |
| `checksums.txt` | SHA-256 manifest |
| `*.sbom.json` | Software bills of materials generated by Syft |

GoReleaser derives `VERSION` from the Git tag. The Wails executable is
dynamically linked against GTK and WebKitGTK, so releases are built on Ubuntu
24.04 for the supported Linux target.

## Validate a snapshot

The Makefile pins the GoReleaser version used by CI and runs it through
`go run`, so a global installation is optional.

Validate only the configuration:

```sh
make goreleaser-check
```

Build a snapshot archive, Arch package, and checksum manifest:

```sh
make package
```

Run the complete local release gate:

```sh
make release-check
```

The gate checks documentation, builds the frontend, runs all Go tests,
validates the GoReleaser configuration, builds both distributions, and verifies
their checksums. Snapshot builds skip SBOM generation so Syft is not required.

Artifacts are written to `dist/`, which GoReleaser cleans before each build.
To use a matching globally installed GoReleaser binary:

```sh
make release-check GORELEASER=goreleaser
```

## Prepare a version

1. Choose the next semantic version.
2. Update `VERSION` for ordinary `make build` output.
3. Move relevant `Unreleased` changelog entries under a dated version heading
   and update comparison links.
4. Run `make release-check`, `git diff --check`, and `go vet ./...`.
5. Commit the release changes and push `main`.
6. Wait for CI on `main` to pass.

Do not reuse or move an existing release tag. If a published release needs a
correction, increment the patch version.

## Publish from GitHub Actions

Create and push an annotated tag matching the prepared version:

```sh
git tag -a vVERSION -m "ThemeTime VERSION"
git push origin vVERSION
```

The `v*` tag triggers `.github/workflows/release.yml`. The workflow installs
build dependencies and Syft, runs the tests, invokes the pinned GoReleaser
version, and creates the GitHub release.

Before announcing the release, confirm that the workflow succeeded and the
release contains:

- the portable `.tar.gz` archive;
- the Arch `.pkg.tar.zst` package;
- `checksums.txt`;
- archive and package SBOMs; and
- GitHub build-provenance attestations.

The workflow also stores the release files as a GitHub Actions artifact.

## Verify artifacts

Verify downloaded files against the checksum manifest:

```sh
sha256sum --ignore-missing --check checksums.txt
```

Verify a GitHub artifact attestation:

```sh
gh attestation verify themetime_VERSION_linux_amd64.pkg.tar.zst \
  --repo RedUndercover/themetime
```

Inspect a portable archive before publishing:

```sh
tar -tzf dist/themetime-VERSION-linux-x86_64.tar.gz
```

It should contain all four executables, project metadata, canonical
documentation, desktop integration, systemd units, the icon, and the Polkit
policy. The Arch package should place executables under `/usr/bin` and include
the corresponding integration files under `/usr/lib` and `/usr/share`.

## Version metadata

`make build` embeds the value from `VERSION` and the current short commit in
the CLI:

```sh
./bin/themetime version
```

GoReleaser embeds the tag-derived version and release commit. Both build paths
use `-trimpath` so local source paths are omitted from binaries.
